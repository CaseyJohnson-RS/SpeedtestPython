# Speedtest — замер скорости скачивания

Скрипт скачивает файл по URL несколько раз подряд и считает скорость загрузки.

## Требования

Python 3.8+. Сторонние библиотеки не нужны.

## Запуск

```bash
python main.py <url> [-n 10] [--timeout 30]
```

| Параметр    | По умолчанию | Описание                                  |
|-------------|--------------|-------------------------------------------|
| `url`       | —            | Адрес файла для скачивания                |
| `-n`        | 10           | Число замеров (прогрев не входит)         |
| `--timeout` | 30           | Таймаут одного запроса, с                 |

Пример:

```bash
python main.py https://example.com/big-image.jpg -n 10
```

## Как считается

1. Сначала выполняется один прогревочный запрос. Он не учитывается, потому что в него входят DNS-запрос и холодные кэши.
2. Затем идут `n` последовательных запросов. Для каждого фиксируется:
   - **задержка**: время от отправки запроса до получения заголовков ответа;
   - **передача**: время скачивания тела ответа;
   - **скорость** = объём / время передачи, то есть без учёта задержки.
3. В итоге выводятся медиана скорости (основной показатель), среднее ± стандартное отклонение, минимум и максимум, медиана задержки, общий объём и среднее полное время запроса.

Скорость выводится в МБ/с и Мбит/с (1 МБ = 10⁶ байт). Провайдеры обычно указывают тариф в Мбит/с.

## Оговорки

- **Нужен большой файл, от десятков МБ.** На маленьком файле передача длится миллисекунды, а часть данных уже лежит в буфере сокета к началу отсчёта. Из-за этого скорость завышается и сильно скачет.
- **Один поток.** Одно TCP-соединение часто не загружает канал полностью, особенно при большой задержке. Speedtest и подобные сервисы качают в несколько потоков, поэтому их результат может быть выше.
- **Измеряется путь до конкретного сервера.** Результат ограничен самым узким местом: вашим каналом, сервером, CDN или маршрутом. Это не обязательно скорость вашего тарифа.
- **Кэширование.** Заголовок `Cache-Control: no-cache` CDN и прокси могут игнорировать. Тогда отдача идёт из ближайшего кэша.
- **Каждый запрос открывает новое соединение.** Из-за TCP slow start на коротких загрузках скорость занижается. Задержка рукопожатия в скорость не входит, но попадает в «среднее время запроса».
- **Фоновый трафик.** Другие загрузки, обновления, VPN и Wi-Fi искажают результат. Для чистого замера лучше подключаться по кабелю и закрыть лишнее.
- **Нагрузка на чужой сервер.** Многократное скачивание тяжёлого файла создаёт нагрузку. Лучше использовать предназначенные для тестов файлы или свой сервер.
